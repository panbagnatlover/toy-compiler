Goal: A compiler that can compile without SSA. Also
handles nested functions. Memory unsafe. No garbage
collection.

Memory is untyped in IR.
Each operand in IR carries type information.
Interprocedural analysis is 1-context sensitive.
Run CFG simplification pass every time a task changes
instruction (e.g., optimization, selection, allocation).
Graph is irreducable, i.e., no jump from outside a loop
to the middle of a loop.

variable { // location of memory addresses
    bool is_reg; // whether the variable is a virtual register
    type;  // memory, int, float, array, etc.
    name;
    int location; // if is_reg, location is a register; else, stack offset
};

operand {
    union {
        *variable;

        constant {
            type;
            value;
        };
    }

    Inst *inst;

    size_t ind;  // Index in pool
}

5: How to do long range splitting? Counterexamples
Decision: no rematerialization. No "long range splitting",
but block splitting should take care of this scenario.
- How long range splitting should be done in theory:
If x is split at block A,
insert MOV x1, x at the split point in A, and trace the
CFG to replace x with x1, until the first block that
meets the following conditions:
    - If block B has multiple predecessors, at least one of
    them other than the branch consisting of A has x live_out,
    insert MOV x, x1 at the end of the branch consisting of A
    before the jump instruction.
    - Else if block B has two successors, and x is live_in in both
    successors, insert MOV x, x1 before the jump instruction
    - Else if block B has two successors, and one of them has
    x live_in, continue tracing the other branch.
- Block splitting: For candidate blocks, load before first use
or def, and spill after last use. This means, create a new
spill range that consists of the block parts being spilled,
then for each split candidate block, create a new range. No
MOV insertion in this case.
